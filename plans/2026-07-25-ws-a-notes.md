## Architecture

Mirrors `focus-flow.mjs`'s capture/analyze split, but capture is now real (not deferred to
an interactive MCP session, since browser MCP is off on this machine and plain Playwright
is used instead):

- **Capture** (`browserCollectContrastSamples`, `browserCollectTouchTargets`): serialized
  into `page.evaluate`, unavoidably browser-side (DOM/computed-style ancestor walk). Returns
  only raw data — computed color STRINGS and background-image presence, never does color
  arithmetic itself.
- **Analyze** (`analyzeContrastSamples`, `analyzeTouchTargets`, plus `parseColor`,
  `compositeLayers`, `relLuminance`, `contrastRatio`, `isLargeText`): pure functions, zero
  DOM dependency, fully unit-tested with synthetic data. All color math (parsing, multi-layer
  alpha compositing for both background AND semi-transparent foreground, luminance, ratio)
  lives here exactly once.
- Findings match static-audit.mjs's shape (`key, category, severity, check, wcag, level,
  title, affected_users, location, description, fix`) plus `source: 'beacon-tier2-audit@1'`
  per finding (the field name `source` matches static-audit's `--merge-findings` channel,
  so a future merge is a drop-in) and `viewport` + `selector` + `computed` as additional
  evidence fields (dropped by the current merge channel, kept for the standalone tier-2
  artifact — worth a decision if/when step 4 happens).
- The artifact carries no score — `metadata.note` explicitly states these categories are
  findings + evidence only pending the step-4 decision.

## Contrast measurement

- Selects elements with a direct (non-whitespace) text-node child, visible (`display`,
  `visibility`, `aria-hidden`, `[hidden]`, zero-area all excluded — same judgement rules as
  VALIDATION.md L3).
- Effective background: ancestor walk from the element itself outward, collecting raw
  `backgroundColor` strings, stopping at the first fully-opaque layer or the document root
  (default: white canvas). A `background-image` (raster or CSS gradient — no distinction,
  per the plan's wording) anywhere in that walk before opacity makes the sample
  `bgUnresolved`, emitted as a `review`/`tip` finding, never a guessed ratio.
- Foreground alpha < 1 is handled by the SAME `compositeLayers` call (treating the fg color
  as one more layer on top of the same bg stack) — no separate code path, verified by a
  dedicated test (`contrast: semi-transparent fg composites...`).
- Large-text definition: `fontSizePx >= 24` OR (`>= 18.6667` (14pt) AND bold, where bold =
  `font-weight === 'bold'` or numeric ≥ 700). Threshold 4.5:1 normal / 3:1 large (WCAG 2.2
  SC 1.4.3 verbatim).

## Touch-target measurement

- Selector list: `a[href], button, input:not([type="hidden"]), select, textarea, summary,
  [role="button"|"link"|"checkbox"|"radio"|"tab"|"menuitem"|"switch"]`; `disabled` and
  hidden elements excluded, zero-area rects skipped.
- 24×24 CSS px floor (WCAG 2.2 SC 2.5.8), spacing exception implemented per the SC's own
  technique: a 24px-diameter circle centered on an undersized target must not overlap ANY
  other target's bounding rect (`circleOverlapsRect`, O(n²) over the page's target list —
  fine at fixture/single-page scale; `ponytail: flag if a page ever has thousands of
  targets`). Inline / equivalent-target-elsewhere / essential-presentation exceptions are
  NOT implemented (out of scope, noted in VALIDATION.md).
- 44×44 best-practice recorded as `severity:'tip'`, `check:'review'` (never a `fail`),
  applied to ANY target below 44px regardless of how it passed the 24px floor.

## Real-page run (acceptance criterion)

`node core/scripts/tier2-audit.mjs --url <rakuten benchmark snapshot 97.html> --output ...`
completed cleanly at both viewports: **2914 findings** — 190 `tier2-contrast-fail`, 1584
`tier2-contrast-unresolvable`, 15 `tier2-touch-target-fail`, 1125
`tier2-touch-target-advisory`, 0 crashes. 917 contrast samples + 761 touch targets per
viewport.

Two real traps hit and fixed on this run (both explained in code comments):
1. `waitUntil: 'load'` (and even `'domcontentloaded'` alone) hung — the snapshot has
   dozens of blocking `<script src="https://r.r10s.jp/...">` tags to hosts unreachable
   offline. Fixed by routing+aborting all non-local requests when the target is a local
   `file://` snapshot (live `http(s)` targets are left alone, they need real network).
2. Even after that fix it still hung: the page `document.write()`s a protocol-relative
   `<img src="//pzd.rakuten.co.jp/...">` tracking pixel, which resolves against a
   `file://` base to `file://pzd.rakuten.co.jp/...` — on Windows that's a UNC
   network-share lookup, which hangs for a long time resolving a nonexistent host. Fixed
   by requiring the strict triple-slash `file:///` (no-host) form in the allow filter.

## Risks / flags for the reviewer

- **Dependency question (flag explicitly, per the dispatch)**: no `package.json` exists
  anywhere in this repo, so there is no repo-local `playwright` dependency to prefer, and
  none was added. `loadPlaywright()` instead reuses an ALREADY-INSTALLED global
  `playwright` package (a transitive dependency of the globally-installed `dev-browser`
  npm package on this machine, at
  `C:\nvm4w\nodejs\node_modules\dev-browser\node_modules\playwright\index.mjs`) via its
  absolute path, with a `PLAYWRIGHT_MODULE_PATH` env override and a clear thrown error if
  neither resolves. This is machine-specific and will break on a clean checkout or CI
  runner that doesn't happen to have `dev-browser` installed globally. If Tier-2 is meant
  to run in CI or on another machine, this needs either a real repo-local `playwright`
  dependency (first `package.json` in this repo) or a documented install step — flagging
  for a decision, did not add it unilaterally.

  regression corpus + adjudicated wild-sample precision) is NOT done — the real-page run
