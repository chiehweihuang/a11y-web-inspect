## Workstream A — Tier-2 native measurement harness: contrast + touch targets

The measurement layer that makes "not-machine-checkable" categories measurable —
plain Playwright (browser MCP is off on this machine), NO axe dependency in the
harness core.

1. **Harness** (`core/scripts/tier2-audit.mjs`): load URL or local snapshot at
   viewports 320 + 1280 (zoom pass deferred); emit findings in the same shape as the
   static tier with their own engine provenance (static-audit.mjs anticipates
   tier-2 merge with provenance, see the comment near the top). Deterministic where
   possible; timestamps injectable like the static tier.
2. **Contrast measurement**: effective fg/bg per visible text element (walk ancestors
   for backgrounds; image/gradient backgrounds are honestly unresolvable → state,
   not a guess), WCAG 2.2 ratios (4.5:1 body, 3:1 large text), confirmed-fail
   findings carry the computed pair + selector + viewport.
3. **Touch-target measurement**: getBoundingClientRect on interactive elements,
   WCAG 2.5.8 24×24 floor with the spacing exception (neighbor distance), per
   viewport.
4. **Scoring wiring — CORRECTED 2026-07-26, premise below was wrong, do not re-read the
   old text as still true.** This step previously said whether tier-2-measured
   contrast/touch categories enter the scoring denominator was an undecided future
   decision. That premise is FALSE and is retracted here rather than silently reworded:
   `mergeExternalFindings()` (`core/scripts/static-audit.mjs` ~1384-1427) has been the
   SOLE channel for Tier-2/manual findings to enter the scored artifact since commit
   `a1d8cab` (2026-06-21) — deliberately, per that commit's message and the inline
   comment directly above the function, with axe as the originally intended input.
   `tier2-audit.mjs` findings merge through that exact same `--merge-findings`
   mechanism as axe or any manual finding; it is not a new or separately-gated channel,
   and merging already moves the score today whenever it is invoked. Verified
   empirically at HEAD: baseline contrast (0 pass/0 fail) reads `not-machine-checkable`,
   overall 56, coverage 23%; merging 1 external finding → `insufficient-evidence` (still
   56/23%, below `THIN_EVIDENCE_MIN`); merging 3 → contrast `scored` at 23, overall 44,
   coverage 36%.

   What actually remains open (USER DECISIONS, unresolved — none of these is "whether
   merging affects score", which is already settled and already live):
   (a) Does the *default* inspect flow run tier-2 + merge it, so scores move by default —
       or does merge stay an explicit, agent-initiated step (today: `tier2-audit.mjs`
       runs by default at Step 2, but its findings only enter the score if the agent
       separately builds a findings file and passes `--merge-findings` at Step 6)?
   (b) Is `THIN_EVIDENCE_MIN = 3` the right thin-evidence threshold for tier-2 sources
       that can produce hundreds of checks per page, where a single merge call can
       instantly clear it (see the "merging 3 → scored" case above)?
   (c) How does the report distinguish a static-only score from a tier-2-inclusive
       score, so the two are never confusable as the same number? (Partial,
       documentation-only step taken 2026-07-26, no scoring change: see the merge
       warning in `core/content/inspect.md` Step 6 and
       `plans/2026-07-26-merge-scoring-note.md`.)
5. Validation: hand-verified fixture GT for contrast pairs and target sizes; FP
   calibration round on a benchmark sample; VALIDATION.md L2 entries for every
   threshold chosen; hakuso gate with empirical probes.

## Workstream B — static contrast reference value (evidence line, never a score)

Statically-resolvable literal pairs only (inline styles / same-file style blocks
where the pair is certain). Render as a findings-layer evidence line
(「可靜態解析的 N 組配對中，M 組低於 4.5:1」), never a ring score; the category stays
review-only in static tier with the tier-2 pointer. FP calibration before shipping.

## Workstream C — axe optionalization

Tier 1 is already axe-free. Rewrite core/content/inspect.md: axe-core drops from
required baseline to optional cross-check; Beacon-native tier-2 (Workstream A) is the
default browser layer; axe results, when present, merge as secondary provenance. The
contrast verification gate accepts EITHER native tier-2 contrast OR axe. The honest
no-browser fallback (requires_live_audit + unverified finding) stays. Target is
"axe optional", not "axe zero" — the ARIA-validity rule block remains axe's
hardest-to-replace value and is out of scope here.

## Workstream D — telemetry consent + missed-case report form (build AFTER user nod)

Design already fixed (2026-07-22 handoff): gateway endpoint + GitHub issue form.
Privacy red line unchanged: automatic upload of a user's raw findings is never built;
key-level telemetry + explicit case submission only. Do not start without the user's
explicit go.
